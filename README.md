- видео с выбором доступного разрешения;
- MP3, GIF до 30 секунд, субтитры и превью;
- TikTok photo posts через `gallery-dl`;
- автоматическая загрузка ссылок в группах (до 720p);
- ограниченная очередь, несколько воркеров, прогресс и отмена;
- плейлисты с настраиваемым лимитом элементов;
- локальный Telegram Bot API для файлов до 2 GB;
- SQLite-статистика и административная рассылка;
- автоматический fallback с видео/аудио на документ, если Telegram отвергает формат.

## Команды бота

- `/start`, `/help` — справка;
- `/status` — активные задачи пользователя;
- `/cancel` — отмена своих задач в текущем чате;
- `/stats` — личная статистика;
- `/admin`, `/broadcast`, `/stats_global` — функции администратора.

## Проверка надёжности

`python -m pytest -q` проверяет дедлайн, отмену и аварийное завершение рабочих процессов,
проверку TikTok-переадресаций и отсутствие повторной отправки при потерянном ответе Telegram.
`ruff check .` и `git diff --check` проверяют код и оформление изменений.

Загрузки и получение метаданных выполняются в отдельных процессах. При отмене или
превышении дедлайна процесс останавливается вместе с дочерними процессами на POSIX.
Временные файлы ограничены тройным лимитом загрузки (для слияния и конвертации);
при остатке менее 64 MiB операция останавливается. Логи ротируются: 5 MB и две копии.
SQLite использует rollback journal вместо WAL для совместимости с сетевым диском хостинга.

Очередь остаётся в памяти: после полного перезапуска незавершённые задания нужно отправить заново.
Тесты не заменяют проверку доставки файлов через реальный Telegram и лимитов памяти хостинга.
